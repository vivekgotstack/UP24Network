# UP24Network working agreement

- Motto: Learn the reason. Build one small working slice. Upgrade when the need is real.
- Work in small, reviewable milestones. Do not implement the entire roadmap in one turn.
- Explain the purpose of each significant change and what the user should learn from it.
- Keep tool use and output focused to conserve the user's credits.
- Begin with a Spring Boot modular monolith, Spring Modulith, PostgreSQL, and a Next.js frontend.
- First product milestone: admin login, draft creation, publication, and a public article page.
- Modules expose explicit APIs or events; do not access another module's internal repositories.
- Introduce microservices, Kafka, and AWS incrementally when justified by a concrete problem.
- Record progress and the next small step in README.md.
- The user handles commits and pushes through the app. Do not commit or push unless explicitly asked.
- Brand name: UP24Network. Use the supplied official logo and its navy/yellow palette with an off-white background.
- Visual direction: classic newspaper typography (Source Serif for reading/headlines, Source Sans for controls), restrained colour, no decorative arrows or generic promotional copy. The user rejected robotic mono typography.
- Use shadcn UI controls and Framer Motion for purposeful animation; respect reduced-motion preferences.
- Stories show video when available, otherwise a photograph. Verify official social profiles before linking them.
- Automatic imports may use only the existing UP24Network website and YouTube channel, as selected by the user. Automation must have persisted admin-controlled toggles and schedules.
